# JavaDevsProject

Порядок мерджа

main
 ├── lead-model                    ← вливается первым (фундамент)
 ├── feat-comparators-validation   ← зависит от lead-model
 ├── feat-sorting                  ← зависит от lead-model
 ├── feat-data-input               ← зависит от lead-model + validation
 └── feat-app-menu                 ← вливается последней (зависит от всех)

Тимлид вливает lead-model в main первым.
Остальные подтягивают main в свои ветки после этого мерджа.
Далее мерджи идут по порядку зависимостей.
Каждый мердж — через Pull Request с ревью тимлида.
После финального мерджа — проверка сборки (mvn clean package) и запуска на main.

Чек-лист перед сдачей

Репозиторий на GitHub создан
5 веток от main, все смерджены обратно через PR
Класс Car с паттерном Builder — ручная реализация
Паттерн Strategy — интерфейс + 3 реализации, ручной код
Сортировка по всем трём полям через компараторы
Запрещённые методы (Arrays.sort, Collections.sort, List.sort) не используются
Три источника данных: файл, рандом, ручной ввод
Валидация данных для всех источников
Программа работает в цикле, выход — только по выбору пользователя
Java Code Conventions соблюдены (именование, пакеты, Javadoc)
Проект собирается и запускается на main
